# kakao-food-card

카카오맵 장소들을 **섹션별 사진 카드 페이지**로 정리해 Artifact로 게시한다. 결과물 예시: [용리단길 맛집 후보](https://claude.ai/artifact/XSna3FBD714cLKVtd4N2aV) (해산물/그 외 2섹션, 12곳, 판정·근거 태그 포함).

도구: `S="${CLAUDE_PLUGIN_ROOT}/skills/kakao-food-card/scripts/kfc.py"`, 작업 폴더 `W=<스크래치패드>/kfc-<슬러그>`. 카카오 비공식 API는 로그인 없이 된다(`search.map.kakao.com`, `place-api.map.kakao.com` + `Referer`·`pf: web` 헤더). 블로그 근거는 카카오 블로그 탭 목록 + 네이버 블로그 모바일 본문(`m.blog.naver.com`)을 스크립트가 직접 읽는다. 브라우저는 **즐겨찾기 목록 읽기**에만 Aside를 쓴다.

**macOS·Windows 공통** — 아래 명령은 Bash 도구(Windows는 Git Bash)에서 그대로 돈다.
- 파이썬: `PY=python3`(macOS) / `PY=python`(Windows — `python3`는 Microsoft Store 스텁일 수 있음). 처음에 `$PY --version`으로 3.8 이상인지 확인한다.
- `-I`(격리 모드)는 사용자 site-packages를 막는다. Pillow가 필요한 `sheet`·`pick`만 `-I` 없이 실행하고, 나머지는 `-I`를 붙인다.
- Pillow가 없으면 `$PY -m pip install --user pillow`. macOS는 Pillow가 없어도 `pick`이 `sips`로 대체된다(`sheet`는 Pillow 필수).
- 파일 입출력과 출력은 스크립트가 UTF-8로 고정하므로 `-X utf8`은 필요 없다.
- heredoc 안에 따옴표·백틱이 섞인 긴 파이썬을 넣으면 Bash 도구가 깨질 수 있다. 긴 보조 스크립트는 Write로 파일을 만든 뒤 실행한다.

## 판정 기준 (고정값 — `kfc.py` 상단 상수와 같다)

**관문(후보에 넣을지)** — `scan`이 적용한다.
- 카카오 평점이 보이면 **3.0 이상**만 후보.
- 평점이 비공개(리뷰창 닫힘)여도 아래 중 하나면 후보: 카카오 인기 맛집 태그 / 메뉴 랭킹 **30위 이내** / 블로그 후기 **300건 이상**.
- 카페·디저트(카테고리 `카페`·`간식`)는 기본 제외(`--cafe`로 포함).
- 지역은 **지정 역에서 도보 10분 안**(`--near`·`--walk`)으로 거른다. 직선거리 × 1.25 ÷ 분당 67m로 계산한 예상 시간이다.
- **위 기준에 없는 이유로 후보를 빼지 않는다.** 쇼핑몰 매장, 체인점, 분위기가 안 맞아 보이는 곳도 기준을 통과하면 후보다(체인은 태그로만 표시). 범위를 좁히거나 넓히고 싶으면 사용자에게 먼저 묻는다.

**카드 태그** — `fetch`·`tag`가 계산한다. 태그는 **제외 사유가 아니다**(정보로만 보여 준다).
| 태그 | 종류 | 조건 |
|---|---|---|
| 리뷰 의심 | 주의 | 의심 5점(작성자 리뷰 **1~2개** 계정, 또는 리뷰 5개 이상인데 **평균 5.0**인 계정)이 **7일 안에 3건 이상** 몰림. 툴팁에 기간·건수·의심 리뷰를 뺀 평균 |
| 최근 하락 | 주의 | 의심 리뷰를 뺀 최근 6개월 리뷰가 5건 이상이고, 그 평균이 전체 평균보다 **0.5점 이상** 낮음 |
| 평점 비공개 | 참고 | 카카오 평점이 없음. 툴팁에 후보로 넣은 근거(태그·랭킹·블로그 수) |
| 리뷰 적음 | 참고 | 카카오 리뷰 **10건 미만**(제외하지 않음) |
| 최근 리뷰 없음 | 참고 | 평점이 보이는 가게인데 마지막 리뷰가 6개월 넘음(폐업·휴업 확인 권유) |
| 비싼 편 | 참고 | 카카오 가격대가 최고 단계(₩₩₩₩₩)일 때만 |
| 체인점 | 참고 | 카카오 프랜차이즈 분류(`catetype` G) 또는 상호 끝에 지점명(○○점) |
| 예약 가능 | 장점 | 카카오 매장 정보에 '예약가능'(원격 줄서기만 되는 곳도 이렇게 나올 수 있다고 툴팁에 밝힘) |
| 근거 N | 장점 | Claude가 고른 블로그 후기 인용(아래 3단계). 툴팁에 링크·인용·작성자·날짜 |

태그는 PC에선 마우스를 올리면, 폰에선 탭하면 툴팁이 펼쳐진다.

## 1. 장소 목록 확보

**A. 지역 검색 모드** — "○○ 맛집 찾아줘"처럼 지역만 받았을 때.
```bash
$PY -I $S scan $W "용리단길 맛집" "용리단길 해산물" "신용산역 맛집" "삼각지역 맛집" "용산역 맛집" ... --near 신용산역,삼각지역,용산역 --walk 10
```
- 검색어는 지역명(동네·역 이름 2~3개) × 요청 키워드(맛집, 원하는 음식 종류, 점심 등)로 10~16개 만든다.
- `--near`에는 그 지역을 둘러싼 역을 모두 넣는다(예: 용리단길 → 신용산역·삼각지역·용산역). 역 하나만 넣으면 반대편 가장자리가 잘린다. `--walk` 기본 10분.
- `--area`(지번 주소의 동 이름)는 사용자가 동 단위로 범위를 정했을 때만 쓴다. 동 경계에 걸친 가게가 잘리므로 임의로 쓰지 않는다.
- 가게마다 패널을 받아 관문을 적용하고 `scan.json`과 후보표(평점·리뷰 수·블로그 수·인기 태그/랭킹·가장 가까운 지정 역과 도보 분·가격대·체인)를 출력한다. 패널은 `raw/`에 캐시돼 다시 돌려도 새 가게만 받는다(가게당 약 1.2초).
- **최종 선정(Claude)**: 후보표에서 10~12곳을 고른다.
  - 사용자 요청 비율을 지킨다(예: "해산물 위주, 해산물만은 말고" → 해산물 2/3, 그 외 1/3).
  - **같은 카카오 업종(`cat`)은 최대 3곳**.
  - 평점·리뷰 수·랭킹을 우선하되, 평점 비공개라도 인기 신호가 강하면 넣는다.
  - 태그만으로 빼지 않는다. 같은 조건이면 주의 태그가 없는 곳을 먼저 고른다.
  - 쇼핑몰·체인 여부로 빼지 않는다(관문 기준과 같다).
- 고른 장소는 **ID로** 2단계에 넘긴다(동명 가게 혼동 방지).

**B. 가게 이름 목록**이면 바로 2단계.

**C. 장소 링크**(`map.kakao.com/?itemId=…`, `place.map.kakao.com/<id>`)가 하나뿐이면, 사용자가 원하는 건 대개 그 가게가 저장된 **즐겨찾기 그룹 전체**다. Aside로 확인한다:
- `aside guide`·`aside guide repl`을 먼저 읽는다(aside-browser 스킬 규칙).
- `aside repl`은 호출마다 세션이 끝나므로 **한 번의 호출 안에서** `openTab('https://map.kakao.com/')` → snapshot에서 `link "즐겨찾기"` 클릭 → 그룹 목록에서 대상 그룹 `link "<그룹명>"` 클릭 → snapshot으로 장소명·주소를 읽는다. ref는 정규식으로 snapshot tree에서 뽑는다.
- 장소 링크(`action=addFavorite`)를 열면 나오는 그룹 선택 레이어의 "저장됨 <그룹명>"으로 소속 그룹을 알 수 있다. **그 레이어의 그룹 항목은 클릭하지 않는다**(즐겨찾기 토글됨).
- 그룹이 모호하면 사용자에게 묻는다.

## 2. 데이터 수집·판정

```bash
$PY -I $S fetch $W 1519844904 16329490 ...              # 카카오 장소 ID (scan 결과)
$PY -I $S fetch $W "가게1" "가게2" ... --region 부천     # 또는 가게 이름 + 주소 필터용 지역명
```
- 최신 리뷰 최대 3페이지(약 60건) + 추천순 1페이지를 받아 태그를 계산하고, `data.json`과 리뷰 다이제스트(태그 이유, 의심 리뷰에 `[신규계정]`·`[전부5점]` 표시)를 출력한다. `digest`로 재출력.
- 이름으로 받았으면 결과 주소가 의도한 가게인지 확인한다(동명 가게 주의).
- 판정 기준을 바꿨으면 `$PY -I $S tag $W`로 저장된 원본에서 태그만 다시 계산한다(재수집 없음).
- 패널 필드: `find_way.subway`(역·출구·도보), `kakaomap_review.score_set`, `trend_rank`(인기 태그·메뉴 랭킹), `ai_mate`(AI 요약·블로그 키워드·가격대), `menu`, `open_hours`(7일), `visitor`(요일×시간대 방문자 → 카드의 붐빔 막대).

## 3. 근거 고르기 (블로그 후기)

```bash
$PY -I $S blogs $W --n 10     # 장소마다 블로그 후기 10건 + 네이버 본문 → raw/ID-blogs.json
```
- 출력 표시: `[광고]` 협찬 문구(원고료·제공받아·체험단 등) 또는 체험단 배너(레뷰·리뷰노트 등 이미지 주소) / `[몰림]` 같은 날 후기 3건 이상(체험단 일괄 게시 가능성) / `[OK]`. `+`는 맛 칭찬 문장 후보, `-`는 본문의 부정 표현.
- **근거는 `[OK]` 후기에서만** 장소당 0~2건 고른다. 기준:
  - 맛에 대한 구체적 서술(메뉴·식감·풍미)이 있는 문장. "맛집이에요" 같은 상투어·해시태그·위치 안내는 쓰지 않는다.
  - 인용은 본문 문장 그대로(줄이기만 가능, 고치지 않음).
  - 쓸 만한 `[OK]` 후기가 없으면 근거를 비워 둔다(억지로 채우지 않는다). 체험단 글이 많았다는 사실은 `sum`에 적는다.
- `data.json` 각 장소의 `ev`에 채운다: `[{"title","url","quote","author","date"}]` (title·url·author·date는 `raw/ID-blogs.json`에서 그대로).

## 4. 섹션 나누기·리뷰 요약 (Claude가 직접 작성)

`data.json`의 각 장소에 채운다:
- `section`: 사용자가 말한 분류의 key(예: 해산물 `sea` / 그 외 `land`). 분류 지시가 없으면 카테고리로 자연스럽게 2~3개.
- `sum`: 2~3문장. 마침표로 끝내야 문장별 줄바꿈된다. 칭찬만 옮기지 말고 **호불호·저평점 후기 패턴과 태그 판정(의심·하락·체험단)**을 반영한다.
- `pros` / `cons`: 짧은 구 2~3개씩.

`meta.json`을 쓴다(`day`는 선택 — 카드의 기본 요일, 없으면 보는 날 요일):
```json
{"title": "용리단길 맛집 후보", "subtitle": "삼각지역과 신용산역 사이 12곳이에요. 해산물 8곳, 그 외 4곳으로 나눴어요. 사진 위 숫자는 가장 가까운 역 출구에서 걸어가는 시간이에요.",
 "note": "평점·리뷰 수·도보 시간·메뉴·영업시간·시간대별 방문자는 카카오맵 기준(YYYY년 M월 D일 조회). 태그를 누르거나 마우스를 올리면 판정 이유가 나와요. '리뷰 의심'은 리뷰가 1~2개뿐인 계정이나 어디서나 5점만 주는 계정의 5점이 일주일 안에 3건 이상 몰린 경우예요. '근거'는 협찬 문구나 체험단 배너가 없고 같은 날 몰리지 않은 블로그 후기에서 맛 이야기만 골랐어요. 영업시간은 가기 전에 카카오맵에서 확인해 주세요.",
 "day": "토",
 "sections": [{"key": "sea", "label": "해산물", "sub": "회 · 장어 · 생선구이", "tone": "cool"},
              {"key": "land", "label": "그 외", "sub": "양식 · 곰탕 · 고기", "tone": "warm"}]}
```
`tone`은 `warm`(주황) / `cool`(파랑).

## 5. 대표 사진 (음식 위주, 반드시 눈으로 확인)

```bash
$PY -I $S photos $W --n 8                 # 카카오 '음식' 태그 사진 → cand-food/
$PY $S sheet $W --dir cand-food           # 컨택트시트 (Pillow 필요해서 -I 없이)
```
- 시트를 Read로 보고 **첫 장이 그 가게 대표 메뉴**(곱창집이면 곱창판, 횟집이면 회)가 되게 고른다. 음식 태그여도 찌개·볶음밥·사이드만 나오는 경우가 흔하다. 같은 사진 중복, 워터마크·글자 얹힌 사진은 피한다.
- 대표 메뉴가 없으면 `--src all`(가게 등록 사진 포함) 또는 `--src blog`(블로그 후기 사진)로 `--ids`를 좁혀 다시 받는다.
- 확정: `$PY $S pick $W <id> cand-food/<id>-3.jpg cand-all/<id>-0.jpg ...` (4장 권장, 첫 장이 대표). Pillow로 변환하므로 `-I` 없이 실행한다.

## 6. 빌드·확인·게시

```bash
$PY -I $S build $W     # site/index.html 생성, 게시할 img 파일 목록 JSON 출력
```
- section·imgs·sum이 빠진 장소가 있으면 빌드가 멈춘다.
- 게시 전 확인(권장): 페이지 스크립트를 뽑아 `node --check`, 헤드리스 Edge/Chrome으로 `--screenshot` 해서 Read로 본다. 폰 폭은 브라우저 최소 창 폭 때문에 `--window-size=390`이 안 먹으니, 390px `iframe`으로 감싼 페이지를 찍는다.
- Artifact 게시: `file_path=$W/site/index.html`, `root=$W/site`, `files=`(build가 출력한 목록), 첫 게시 때 `icon: "food"`. 같은 file_path로 재게시하면 URL이 유지된다. 다른 작업 폴더에서 같은 페이지를 갱신하려면 `url`을 넘기고, 빠진 가게 사진은 `files`에 `null`로 지운다.
- 페이지에 들어 있는 것: 정렬 버튼(가까운 순/평점 순/리뷰 많은 순), **요일 선택**, 섹션 바로가기, 사진 썸네일 전환, 카카오맵처럼 생긴 인기 맛집 태그, **판정·근거 태그(호버/탭 툴팁)**, 리뷰 요약, 대표 메뉴 가격, **선택한 요일의 영업시간과 시간대별 붐빔 막대(가장 붐빔 빨강, 점심·저녁 덜 붐빔 초록)**, 노란 "카카오맵에서 보기" 버튼, 라이트/다크 테마.

## 7. 보고

- 섹션별 표: 가게 / 평점(리뷰 수) / 역·출구·도보 시간 / 태그.
- 눈에 띄는 점: 의심·하락 태그가 붙은 곳과 이유, 체험단 글이 많았던 곳, 근거를 못 찾은 곳, 사진을 다른 출처에서 가져온 가게.
- **공유**: 처음엔 비공개다. 페이지 오른쪽 위 Share에서 링크 공유를 켜야 친구가 열 수 있다(Claude는 공유 설정을 바꿀 수 없음). 페이지엔 공개 가게 정보와 공개 블로그 링크만 있고 개인 즐겨찾기·계정 정보는 없다. 사진은 리뷰어 사진이라 지인 공유는 괜찮지만 공개 게시는 피하라고 안내한다.
