# coupang-search — 쿠팡 상품 조사

쿠팡은 짧은 시간에 페이지를 많이 열면 "요청하신 페이지의 사용권한이 없습니다 / 사용권한이 제한된 페이지입니다" 차단 페이지를 띄운다. 상품 상세 페이지를 연달아 열거나 작업 두 개를 동시에 돌렸을 때 막혔고, 검색 목록 페이지만 한 번에 하나씩 열었을 때는 15회 연속 막히지 않았다(2026-10). 이 스킬은 그 방식을 고정하고, 검색 간격을 기록으로 조정한다.

브라우저 작업은 Aside(`aside` CLI)로 한다. Aside가 없으면 같은 규칙으로 다른 브라우저 도구를 써도 되지만, 그 경우 히스토리 `--note`에 도구 이름을 적는다.

## 0. 간격 확인

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/coupang-search/scripts/pacing.py" status   # Windows는 python
```

- `간격`이 이번에 쓸 검색 간 대기(초)다.
- `단축 제안`이 있으면 사용자에게 알리고, 동의하면 `pacing.py set-interval <초>`로 바꾼다. 묻지 않고 바꾸지 않는다.
- 오늘 누적이 이미 많으면(예: 40회+) 사용자에게 알리고 진행 여부를 묻는다.

## 1. 규칙 (반드시)

- **검색 결과 목록 페이지만** 연다. 상품 상세 페이지는 열지 않는다(목록에 상품명·가격·평점·리뷰 수·URL이 다 있다).
- **동시 실행 금지.** Aside 세션 하나, 탭 하나. 다음 검색은 같은 탭에서 주소만 바꾼다.
- 검색과 검색 사이에 **현재 간격(초) 이상** 기다린다.
- 차단 문구가 보이면 **즉시 전부 멈춘다.** 재시도하지 않는다.
- 끝나면 연 탭을 닫는다. 로그인·구매·장바구니·글쓰기 금지.

검색 주소(쿠팡 랭킹순, 72개): `https://www.coupang.com/np/search?q=<검색어>&sorter=scoreDesc&listSize=72`

## 2. 실행

검색어를 **4개 안팎씩 묶어** 같은 세션을 이어 간다. 출력은 반드시 파일로 받는다(터미널 출력은 잘린다).

첫 묶음:

```bash
aside -m claude-code/claude-sonnet-5-5 --effort low "<프롬프트>" > <작업폴더>/b1.txt 2>&1
```

세션 ID는 출력 첫 줄(`created new session: <id>`)에 있다. 다음 묶음부터:

```bash
aside session resume <id> "<프롬프트>" > <작업폴더>/b2.txt 2>&1
```

프롬프트 틀(`{interval}`·검색어만 바꾼다):

```
정보 추출 작업. 로그인·구매·장바구니·글쓰기 금지. 원문 그대로 항목별로만 반환, 요약·추천 금지.
규칙: 쿠팡 '검색 결과 목록 페이지'만 연다(상품 상세 페이지 금지). 탭 하나만 쓰고 다음 검색은 같은 탭에서 주소만 바꾼다.
검색과 검색 사이에 최소 {interval}초 기다린다.
'사용권한이 없습니다', '사용권한이 제한된', 'Access Denied' 같은 차단 문구가 보이면 즉시 모든 작업을 멈추고 재시도하지 않는다.
끝나면 연 탭을 닫는다.
검색 주소: https://www.coupang.com/np/search?q=<검색어>&sorter=scoreDesc&listSize=72
검색어 순서대로: 1) … 2) … 3) … 4) …
각 검색마다 광고(AD) 상품은 건너뛰고 상위 10개: 순위. 상품명 | 판매가(할인이면 원가 → 할인율 → 판매가) | 평점 | 리뷰 수 | URL(coupang.com/vp/products/숫자 까지).
맨 끝에 반드시 아래 두 줄을 적는다:
실제 대기: <검색 사이 실제로 기다린 초>
차단됨: 없음  (막혔으면 → 차단됨: <몇 번째 검색> <검색어>, 첫 검색 후 <경과 분>분)
```

결과가 잘렸으면 **페이지를 다시 열지 말고** `aside session resume <id> "페이지 새로 열지 말고 N번 목록만 다시 출력해줘"`로 받는다.

## 3. 묶음마다 확인

결과 파일 끝의 `차단됨:` 줄을 본다.

**막혔을 때** — 남은 묶음은 진행하지 않는다.

```bash
python3 ".../pacing.py" log --searches <이번 작업에서 연 검색 수, 막힌 것 포함> --actual <실제 대기> --blocked-at <작업 전체 기준 순번> --elapsed-min <경과 분> --note "<주제>"
```

사용자에게 그대로 보고한다:
- 막힌 시점의 간격(설정 X초, 실제 Y초), 작업 전체에서 몇 번째 검색, 첫 검색 후 경과, 오늘 누적
- 스크립트가 올린 다음 간격(1.5배)
- 그때까지 받은 결과는 쓰고, 남은 검색어는 몇 시간 뒤(최소 1~2시간)에 다시 하자고 제안. 막힌 상태에서 다시 열면 차단이 길어질 수 있다.

**끝까지 안 막혔을 때**:

```bash
python3 ".../pacing.py" log --searches <총 검색 수> --actual <실제 대기> --note "<주제>"
```

출력에 `단축 제안`이 나오면 사용자에게 제안한다(같은 간격으로 3번 연속, 각 10회 이상 무차단일 때만 나온다. 최소 10초).

## 4. 고르기

- 기준: 쿠팡 랭킹순(광고 제외) + 리뷰 수. 같은 상품 번호의 색상·옵션 중복은 하나로 친다.
- 평점 3.5 이하, 리뷰 수 표시 없음은 대안이 없을 때만 넣고 단점에 적는다.
- 품목마다 고르는 기준(크기·재질 등)이 있으면 그것을 먼저 거른다. 목록에 없는 치수·사양은 "미확인"으로 적고 지어내지 않는다.
- 결과 표: 순위 | 제품(링크) | `쿠팡 <가격> · 리뷰 <수>` | 장점 | 단점. 가격은 조사 날짜와 함께 적는다(로그인 안 한 가격이라 쿠폰·와우 할인 미반영).

## 히스토리

`~/.claude/coupang-search/`에 기기별로 쌓인다(플러그인 업데이트로 지워지지 않는다).
- `state.json`: 현재 간격, 마지막 변경 시각
- `history.jsonl`: 실행마다 한 줄 — 시각, 기기, 설정·실제 간격, 검색 수, 오늘 누적, 차단 순번·경과, 메모
- 보기: `pacing.py history -n 20`
