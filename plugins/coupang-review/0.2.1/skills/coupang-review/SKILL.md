# coupang-review — 쿠팡 후기 텍스트 작성

**입력**: 상품 링크 + 사용자 경험(대충 말해도 됨) + 사진(있으면).
**출력**: 복사해서 붙여 넣을 **텍스트만**(한줄 요약 + 상세리뷰).
올리기·사진 첨부·별점 선택은 사용자가 쿠팡 앱에서 직접 한다.

쿠팡 체험단은 **신청제가 아니라 쿠팡이 골라 초대**한다.
공식 기준은 "와우 회원 중 상품평 활동이 활발하고 양질의 구매후기를 등록한 고객"이고, **상품평 랭킹과는 무관**하다.
리뷰 개수·도움돼요 수·글자 수 합격선은 공개되지 않았다.
그래서 이 스킬은 공식 기준 세 가지에만 맞춘다.

1. 와우 회원 유지(필수 조건)
2. 활발함: 몰아 쓰지 말고 **산 물건마다 꾸준히**
3. 양질: 써 본 사람만 아는 구체적인 내용 + 아쉬운 점도 솔직하게

근거와 출처: `references/selection-research.md` (2026-11-27 조사).
선정 기준을 물으면 이 문서를 읽고 공식과 경험담을 구분해 답한다.

## 0. 절대 규칙

- **사용자가 말한 경험과 사진에 보이는 것만 쓴다.**
  - 안 써 본 기능, 안 잰 수치, 안 겪은 상황을 지어내지 않는다.
  - 허위·과장 후기는 쿠팡 공식 불이익 사유다.
- **다른 사람 리뷰는 질문거리로만 쓴다.** (3절)
  - 남의 경험·수치·문장을 사용자 경험처럼 옮기지 않는다.
  - 문장을 베끼지 않는다. 다른 리뷰와 문장이 겹치면 복붙·AI 글처럼 보인다.
- 상세페이지 스펙·광고 문구를 옮겨 적지 않는다(공식: 스펙 나열은 피할 것).
  - 사용자가 겪은 맥락에서만 쓴다. 예: "가로 60cm라 원룸 책상 옆에 딱 맞았어요".
- **쿠팡에 직접 올리지 않는다.** 로그인·글쓰기·사진 업로드 자동화 금지.
- 리뷰 교환·도움돼요 품앗이·여러 계정은 권하지 않는다.

## 1. 시작: 기록 확인

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/coupang-review/scripts/review_log.py" status   # Windows는 python
```

- 진행 중인 체험단이 있으면 마감(D-day)을 먼저 알린다.
- 마지막 리뷰가 2주 넘었으면 "최근 산 것 중 후기 안 쓴 게 있나요?"라고 한 번 묻는다.
  - 찾는 곳: 쿠팡 앱 마이쿠팡 → 리뷰 관리 → 작성 가능한 리뷰.
- 말투 메모 `~/.claude/coupang-review/style.md`가 있으면 따른다. 없으면 편한 존댓말(~요).
  - 사용자가 말투를 정해 주면 그 파일에 적어 둔다.
  - 사용자가 직접 쓴 예전 후기를 붙여 주면 그 말투(문장 길이, 어미, 자주 쓰는 표현)를 요약해 적어 둔다.

## 2. 받기

사용자가 준 것을 확인한다. 빠진 게 있으면 그것만 묻는다.

- **링크**: 없으면 받는다. 상품명만 있으면 링크를 달라고 한다.
- **경험**: 키워드·말투 그대로 던져도 된다고 알려 준다. 처음부터 길게 묻지 않는다.
  - 최소로 필요한 것: 산 이유, 써 본 기간, 좋았던 점 1개 이상.
- **사진**: 이미지 파일을 주면 직접 본다.
  - 사진에 보이는 사실(설치된 장소, 색감, 크기 비교 대상, 사용 장면)은 내용에 써도 된다.
  - 사진만 보고 성능·내구성·만족도를 추측하지 않는다.
  - 체험단 후기는 상품 사진이 필수다. 사진이 없으면 "올릴 때 상품 사진 꼭 넣으세요" 한 줄만 알린다.
  - 송장 이름·주소, 얼굴, 창밖 풍경이 찍힌 사진이 있으면 빼거나 가리라고 알린다.
- **체험단 상품인지**: 맞으면 초대일을 받아 5절대로 기록한다.

## 3. 상품 페이지 읽기 (링크마다 1회)

상품명·선택 옵션과, 다른 사람 리뷰에서 **많이 나온 포인트**를 얻기 위해 상세페이지를 한 번 연다.
쿠팡 차단을 피하려고 `coupang-search` 스킬의 간격 규칙을 그대로 따른다.

```bash
P=$(ls -d ~/.claude/plugins/cache/youjeonghan-claude-plugins/coupang-search/*/skills/coupang-search/scripts/pacing.py 2>/dev/null | tail -1)
python3 "$P" status    # '간격'(초)을 확인. 파일이 없으면 간격 40초로 한다
```

Aside로 한 세션·한 탭만 쓰고, 출력은 작업 폴더 파일로 받는다.

```bash
aside --effort low "<아래 프롬프트>" > <작업폴더>/reviews.txt 2>&1
```

```
정보 추출 작업. 로그인·구매·장바구니·글쓰기 금지. 원문 그대로 항목별로만 반환, 요약·추천 금지.
규칙: 탭 하나만 쓴다. 리뷰 다음 페이지로 넘길 때마다 최소 {interval}초 기다린다(같은 페이지 안 스크롤·더보기는 괜찮다).
'사용권한이 없습니다', '사용권한이 제한된', 'Access Denied' 같은 차단 문구가 보이면 즉시 모든 작업을 멈추고 재시도하지 않는다.
끝나면 연 탭을 닫는다.
주소: <사용자가 준 링크, itemId·vendorItemId 유지>
1) 상품명 | 선택된 옵션 | 평점 | 리뷰 수
2) 상품평 영역의 요약·키워드·평가 항목 통계(예: '크기 적당해요 70%')가 있으면 원문 그대로
3) 상품평을 '베스트순'(없으면 기본 정렬)으로 최대 20개: 별점 | 옵션 | 본문 앞 200자 원문. 리뷰 페이지는 최대 2페이지까지만.
맨 끝에 반드시 아래 세 줄:
연 페이지 수: <리뷰 페이지 넘김 포함>

```

끝나면 기록한다(막혔으면 `--blocked-at`까지, 자세한 건 coupang-search 스킬 3절).

```bash
python3 "$P" log --pages <연 페이지 수> --detail <연 페이지 수> --actual <실제 대기> --note "리뷰 참고: <상품명>"
```

막혔으면 상품 페이지 없이 사용자 경험만으로 진행하고, 몇 시간 뒤 다시 보자고 알린다.

### 다른 리뷰에서 뽑을 것

`reviews.txt`에서 **주제만** 뽑는다. 문장은 가져오지 않는다.

- 자주 나온 장점 주제 3~5개 (예: 조립 쉬움, 수납량, 색감)
- 자주 나온 불만 주제 2~4개 (예: 냄새, 흔들림, 사이즈 작음)
- 아무도 말 안 한 빈 곳 (예: 반려동물 집, 원룸, 겨울철 사용) → 사용자 상황과 맞으면 그 후기만의 가치가 된다

## 4. 빈 곳 되묻기

사용자 경험과 3절 주제를 비교한다.
사용자가 아직 말하지 않은 주제 중 **중요한 것 최대 4개**만, 한 번에 짧게 묻는다.

예:
```
다른 후기에서 많이 나온 얘기인데, 직접 겪은 것만 짧게 답해 주세요. 모르면 '모름'.
1. 조립 어렵다는 말이 많던데, 몇 분 걸렸어요?
2. 냄새 얘기가 있던데 느꼈어요?
3. 고양이 있다고 했는데, 올라가거나 긁은 적 있어요?
```

- 답한 것만 쓴다. "모름·안 써 봄"인 주제는 뺀다.
- 다른 리뷰는 사용자 경험과 **비교할 때만** 언급할 수 있다. 사용자가 그 주제를 직접 확인했을 때만.
  - 가능: "냄새 난다는 후기가 있어서 걱정했는데 저는 이틀 지나니 거의 안 났어요"
  - 불가: 사용자가 안 겪은 "조립이 20분 걸렸어요"를 남의 리뷰에서 가져오기
- 되물어도 내용이 짧으면 **짧은 대로 쓴다.** 소모품은 200~300자로 충분하다. 늘리려고 같은 말 반복하지 않는다.
  - 체험단 후기가 200자에 못 미치면 무엇을 더 말해 주면 되는지 하나만 묻는다.

## 5. 쓰기

### 상세리뷰

흐름(고정 틀처럼 보이지 않게, 문단 수·길이는 내용 따라 다르게):

- 산 이유·사용 환경: 1~2문장. 읽는 사람이 "나랑 비슷한가" 판단하게.
- 써 보니: 가장 중요한 경험 2~3개. 숫자·장면·전후 비교.
- 아쉬운 점: 있으면 1~2개. 해결 방법이 있으면 같이.
- 누구에게 맞는지: 한두 문장. 할 말 없으면 생략.

분량:
- 일반 후기: 200~700자. 내용만큼만.
- 체험단 후기: **200자 이상 필수**, 700자 안쪽 권장.

AI 글처럼 안 보이게(쿠팡이 AI를 잡는다는 공식 근거는 없지만, 기계적인 글은 "저품질" 판정에 가깝다):
- **사용자가 쓴 단어·말버릇을 그대로 살린다.** 다듬는 건 맞춤법·순서 정도만.
- 소제목·글머리표·번호 목록 쓰지 않는다. 짧은 문단 몇 개, 문단 사이 빈 줄.
- 장점 3개·단점 1개처럼 딱 떨어지는 대칭 구조를 피한다. 문장 길이도 섞는다.
- 금지 표현: 줄표(—), 이모지 남발, "결론적으로", "전반적으로", "만족스러웠습니다", "가성비 최고", "강추", "~하는 분들께 추천드립니다" 같은 상투어, 광고 문구.
- 상품명 전체를 본문에 반복하지 않는다. "이거", "선반"처럼 사람이 부르는 대로.
- 체험단 문구("무료로 제공받아…")는 **쓰지 않는다.** 쿠팡이 배지와 문구를 자동으로 붙인다.

### 한줄 요약

리뷰 화면에 한 줄 요약 칸이 있으면 쓴다. 가장 중요한 경험 하나를 30자 안쪽으로.
예: "원룸 책상 옆에 딱 맞음, 조립 20분"

### 출력

**텍스트만** 복사하기 좋게 코드블록 하나로 낸다. 설명은 블록 밖에 한두 줄.

````
```
[한줄 요약]
…

[상세리뷰]
…
```
글자 수 N자 · 사진은 올릴 때 직접 넣어 주세요(체험단은 필수)
````

- 사진 순서를 물으면 그때 제안한다: 실사용 장면 → 크기 비교 → 디테일 → 아쉬운 점. 포장 박스만 있는 사진은 뺀다.
- 사용자가 고치라는 부분만 고친다. 사실과 다른 곳이 있다고 하면 바로 뺀다.

## 6. 올린 뒤 기록

사용자가 올렸다고 하면 기록한다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/coupang-review/scripts/review_log.py" add --product "<상품명>" --chars <글자수> --photos <장수> [--video] [--trial] [--url "<링크>"]
```

- `--trial`이면 진행 중 체험단 기록이 완료 처리된다.
- 사진 장수를 모르면 물어보거나 0으로 둔다.

## 7. 체험단 초대가 왔을 때

```bash
python3 ".../review_log.py" invite --product "<상품명>" --date <초대일 YYYY-MM-DD>
python3 ".../review_log.py" ordered --product "<상품명>"   # 주문하면
```

사용자에게 알릴 것(공식 FAQ 기준):
- 주문: 초대일로부터 3일 이내. 주말·공휴일이 끼면 늘어날 수 있으니 앱 안내 날짜 우선.
- 후기: **초대일 포함 14일 이내.** 배송일 기준이 아니다. 받자마자 쓰기 시작한다.
- 한 기수에 상품 1개만. 2개 이상 주문은 불이익.
- 와우 회원을 쿠폰 사용 때까지 유지.
- 판매가 5만 원 이상이면 제세공과금 22%(쿠팡이 대신 냄).
- 쿠폰만 받고 안 쓰거나 기한을 넘기면 다음 선정에 불이익이 있을 수 있다.

## 히스토리

`~/.claude/coupang-review/`에 쌓인다(플러그인 업데이트로 지워지지 않는다).
- `reviews.jsonl`: 리뷰 한 건당 한 줄(날짜, 상품, 글자 수, 사진 수, 영상, 체험단 여부, 링크)
- `invites.jsonl`: 체험단 초대(초대일, 상품, 주문 여부, 완료일)
- `style.md`: 사용자 말투 메모(선택)
- 보기: `review_log.py history -n 20`

쿠팡 페이지 조회 간격 기록은 coupang-search의 `~/.claude/coupang-search/`에 같이 쌓인다(두 스킬이 같은 간격을 공유).
