# coupang-review — 쿠팡 후기 작성

쿠팡 체험단은 **신청제가 아니라 쿠팡이 골라 초대**한다.
공식 기준은 "와우 회원 중 상품평 활동이 활발하고 양질의 구매후기를 등록한 고객"이고, **상품평 랭킹과는 무관**하다.
리뷰 개수·도움돼요 수·글자 수·사진 장수의 합격선은 공개되지 않았고, 경험담도 제각각이다.
그래서 이 스킬은 검증 안 된 공식을 좇지 않고 **공식 기준 세 가지에만** 맞춘다.

1. 와우 회원 유지(필수 조건)
2. 활발함: 몰아 쓰지 말고 **산 물건마다 꾸준히**
3. 양질: 써 본 사람만 아는 구체적인 내용 + 서로 다른 정보를 담은 사진 + 아쉬운 점도 솔직하게

근거와 출처: `references/selection-research.md` (2026-11-27 조사).
사용자가 "선정 기준이 뭐야" 같은 걸 물으면 이 문서를 읽고 공식과 경험담을 구분해 답한다.

## 0. 절대 규칙

- **사용자가 말한 경험만 쓴다.** 안 써 본 기능, 안 잰 수치, 안 겪은 상황을 지어내지 않는다.
  - 허위·과장 후기는 쿠팡 공식 불이익 사유다. 체험단 후보에서 멀어지는 가장 빠른 길이다.
  - 정보가 비면 채우지 말고 묻는다.
- 상품 상세페이지의 스펙·광고 문구를 옮겨 적지 않는다(공식 안내: 스펙 나열은 피할 것).
  - 스펙은 사용자가 직접 확인한 맥락에서만 쓴다. 예: "가로 60cm라 원룸 책상 옆에 딱 맞았어요".
- 다른 사람 후기·사진을 가져오지 않는다(공식 금지, 저작권).
- 리뷰 교환·도움돼요 품앗이·여러 계정은 권하지 않는다. 사용자가 원하면 위험만 알려 준다.
- **쿠팡에 직접 올리지 않는다.** 로그인·글쓰기 자동화는 하지 않고, 사용자가 복사해서 올린다.
- 같은 문장 틀을 상품마다 반복하지 않는다. 매번 그 상품의 경험으로 새로 쓴다.

## 1. 시작: 기록 확인

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/coupang-review/scripts/review_log.py" status   # Windows는 python
```

- 진행 중인 체험단이 있으면 마감(D-day)을 먼저 알린다. 체험단 후기는 일반 후기보다 우선이다.
- 마지막 리뷰가 2주 넘었으면 "최근 산 것 중 후기 안 쓴 게 있나요?"라고 한 번 묻는다.
  - 찾는 곳: 쿠팡 앱 마이쿠팡 → 리뷰 관리 → 작성 가능한 리뷰.
- 말투 기본값이 `~/.claude/coupang-review/style.md`에 있으면 따른다. 없으면 기본은 편한 존댓말(~요).
  - 사용자가 말투를 정해 주면 그 파일에 적어 둔다.

## 2. 경험 받기

사용자가 상품만 말하면 아래를 **한 번에** 묻는다. 이미 말한 건 다시 묻지 않는다.
길게 답할 필요 없다고 알려 준다. 키워드나 말투 그대로 던져 주면 된다.

1. 무엇을, 왜 샀나요? (원래 쓰던 것, 불편했던 점, 고른 이유)
2. 얼마나, 어디서, 어떻게 써 봤나요? (기간·횟수, 집 구조·용도·같이 쓰는 사람이나 반려동물)
3. 써 보니 좋았던 점은? (가능하면 숫자: 시간, 크기, 무게, 전후 비교)
4. 아쉬웠던 점은? (없으면 "없음", 사소한 것도 좋음: 냄새, 조립, 포장, 소음)
5. 어떤 사람에게 맞고, 어떤 사람에게는 안 맞을까요?
6. 별점 몇 점 줄 생각인가요?
7. 사진을 찍었나요? 찍었다면 무엇을요? (이미지 파일을 주면 직접 보고 순서·설명을 제안한다)
8. 체험단 상품인가요? (맞으면 초대일)

- 3·4 중 하나라도 비면 그 부분만 다시 묻는다. 비어 있는 채로 쓰면 "양질"이 안 된다.
- 사용자가 상품 링크를 주고 크기·사양을 확인해 달라고 하면, `coupang-search` 스킬 규칙(페이지 간격·순차·차단 시 중단)으로만 상세페이지를 본다. 확인 못 한 값은 쓰지 않는다.

## 3. 쓰기

### 상세리뷰

구성(선정자 경험담 + 공식 권장에서 겹치는 부분):

1. 구매 이유·사용 환경: 1~2문장. 읽는 사람이 "나랑 비슷한 상황인가"를 판단하게.
2. 써 보니: 가장 중요한 경험 2~3개. 구체적인 숫자·장면·전후 비교.
3. 아쉬운 점: 1~2개. 해결 방법이 있으면 같이(예: "처음엔 냄새가 났는데 하루 환기하니 빠졌어요").
4. 추천 대상: 누구에게 맞고 누구에게 안 맞는지 한두 문장.

분량:
- 일반 후기: 300~700자. 짧은 소모품은 200자대도 괜찮다. 늘리려고 같은 말 반복하지 않는다.
- 체험단 후기: **200자 이상 필수**, 700자 안쪽 권장.

문체:
- 사용자가 쓴 표현을 최대한 살린다. 다듬기만 하고 바꾸지 않는다.
- 짧은 문단 3~5개, 문단 사이 빈 줄. 소제목·글머리표 남발 금지(AI 글처럼 보인다).
- 금지: 줄표(—), 이모지 남발, "결론적으로", "전반적으로 만족", "가성비 최고", "강추합니다" 같은 빈말, 광고 문구 같은 과장.
- 단점을 감추지 않는다. 단점이 있는 후기가 더 믿음을 준다.
- 체험단 문구("무료로 제공받아…")는 **쓰지 않는다.** 쿠팡이 배지와 문구를 자동으로 붙인다.

### 한줄 요약

리뷰 화면에 한 줄 요약 칸이 있으면 쓴다. 가장 중요한 경험 하나를 30자 안쪽으로.
예: "원룸 책상 옆에 딱 맞는 60cm, 조립 20분"

### 별점

사용자가 정한 점수를 쓴다. 본문 내용과 안 맞으면(단점이 큰데 5점 등) 한 번만 짚어 준다.

### 사진 목록

사진은 **서로 다른 정보**를 담게 3~7장을 제안한다(체험단은 상품 사진 필수, 7장 이내 권장).
포장 박스만 있는 사진은 빼라고 안내한다.

| 순서 | 무엇 | 왜 |
|---|---|---|
| 1 | 실제 쓰는 장면(설치·착용·사용 중) | 첫 사진이 대표로 보인다 |
| 2 | 크기 비교(손·휴대폰·A4·사람·주변 가구) | 치수 글자보다 잘 전달된다 |
| 3 | 핵심 디테일(재질·마감·버튼·박음질) | 상세페이지 사진과 다른 실물 |
| 4 | 아쉬운 점이 보이는 컷(있으면) | 신뢰 |
| 5 | 전후 비교·사용 결과(해당되면) | 효과가 보인다 |

- 개인정보 주의: 송장 이름·주소, 얼굴, 집 밖 풍경·창밖, 우편물이 찍히지 않게 안내한다.
- 영상은 필수 아님. 움직임이 핵심인 상품(소음·작동·접이식)만 10~20초 권한다.

### 결과 보여 주기

아래 순서로 복사하기 좋게 낸다.

```
[별점] ★★★★☆ (4점)
[한줄 요약] …
[상세리뷰]
…
(글자 수: N자)
[사진] 1) … 2) … 3) …
[확인] 사실과 다른 곳, 빠진 경험 있으면 말해 주세요.
```

사용자가 고치라는 부분만 고친다. 다 맞다고 하면 쿠팡 앱에서 직접 올리라고 안내한다.

## 4. 올린 뒤 기록

사용자가 올렸다고 하면 기록한다.

```bash
python3 ".../review_log.py" add --product "<상품명>" --chars <글자수> --photos <장수> [--video] [--trial] [--url "<링크>"]
```

- `--trial`이면 진행 중 체험단 기록이 완료 처리된다.

## 5. 체험단 초대가 왔을 때

```bash
python3 ".../review_log.py" invite --product "<상품명>" --date <초대일 YYYY-MM-DD>
python3 ".../review_log.py" ordered --product "<상품명>"   # 주문하면
```

사용자에게 알릴 것(공식 FAQ 기준):
- 주문: 초대일로부터 3일 이내. 주말·공휴일이 끼면 늘어날 수 있으니 앱 안내 날짜를 우선.
- 후기: **초대일 포함 14일 이내.** 배송일 기준이 아니다. 배송이 늦으면 받자마자 쓴다.
- 한 기수에 상품 1개만. 2개 이상 주문은 불이익.
- 와우 회원을 쿠폰 사용 때까지 유지.
- 판매가 5만 원 이상이면 제세공과금 22%가 생긴다(쿠팡이 대신 냄).
- 쿠폰만 받고 안 쓰거나 기한을 넘기면 다음 선정에 불이익이 있을 수 있다.

## 히스토리

`~/.claude/coupang-review/`에 쌓인다(플러그인 업데이트로 지워지지 않는다).
- `reviews.jsonl`: 리뷰 한 건당 한 줄(날짜, 상품, 글자 수, 사진 수, 영상, 체험단 여부, 링크)
- `invites.jsonl`: 체험단 초대(초대일, 상품, 주문 여부, 완료일)
- `style.md`: 사용자 말투 메모(선택)
- 보기: `review_log.py history -n 20`

기록은 "활발함"을 스스로 점검하는 용도다. 쿠팡이 실제로 무엇을 세는지는 공개되지 않았다.
